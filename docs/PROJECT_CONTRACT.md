# Product contract

Warehouse Twin is a SaaS product in development. Each workspace owns its persisted configuration and operational records. This original interface does not claim to reproduce production SCOTI. The live adapter awaits supported API documentation, authentication details, field semantics, and an approved environment. Manual data and CSV import are the current path.

Journey: register → dashboard → configure receive/stage, storage, pack/dispatch → review layout validation → save → inspect/walk → add/import records → guarded workflows → activity and export.

Business rules belong in `src/domain`. Server authorization checks the authenticated workspace on each request. Components and 3D modules render saved state. Never create feature-local inventories. Synthetic data comes from `exampleWarehouse()` and stays explicitly labeled. Editing examples turns edited records into manual data.

Stable logical addresses survive physical offsets and footprint expansion. Layout reductions cannot orphan records or external mappings. Each mutation requires the current warehouse version; stale requests return 409 and require reload. Imports are atomic and replace matching record IDs while retaining other records. Only one docked/held truck may occupy a dock. A cargo ID cannot belong to two docked trucks.

Current operations: expected arrival, whole-manifest receipt into staging with inbound departure, putaway, transfer, pick with order reference, pack, load onto a docked outbound truck, partial/full unload, cycle count with reason, dispatch, hold, and restoration of the pre-hold state. Invalid transitions, excess quantity, wrong areas, holds, and mismatched manifests fail without a partial write. A manually entered hold without previous state needs a manual status edit.

3D is optional enhancement. One meter is one world unit; Y is up. Dock frames lie on the actual exterior wall, with trucks facing outward and trailer rears meeting the threshold. Expected/dispatched trucks are not drawn docked. Cutaway shows labeled transparent near walls; complete-building includes all walls and roof; walking uses a solid shell. SVG plan and address directory remain usable without WebGL. Dashboard thumbnails do not allocate GPU renderers. Dispose GPU resources on replacement. Animation never changes records independently.

Remaining releases: partial receipt/discrepancies, dedicated quality/returns workflows, expanded collision/safety verification, roles, staging deployment verification, approved SCOTI adapter. These are requirements rather than completed capabilities.

Capacity rules constrain physical quantity in one exact unit at a storage, staging, or packing address. Held stock consumes capacity. Cargo ownership cannot be severed through generic edits/imports/deletion. Warehouse removal archives the complete payload; dashboard restore advances its version. See RELEASE_READINESS.md for implemented scope, verified checks and remaining client-launch gates.

Vercel deployments use Neon PostgreSQL through server-only DATABASE_URL. Accounts, sessions, warehouse payloads, archives, and auth attempt buckets share durable server storage. Local development may retain SQLite. Database access is asynchronous, with one PostgreSQL connection per request and explicit transaction boundaries. The public landing renders the canonical example without persisting or mutating it; SCOTI connectivity remains pending.

## Custom 2D design studio

The builder offers a template path and a measured custom-design path. Custom designs save a versioned floor polygon and catalog modules in warehouse configuration; layout generation and validation remain in the domain. Ground-floor template conversion retains all logical addresses. Additional floors prefix addresses with their immutable floor ID, stack by preceding clear height plus a 0.3 m slab, and can be isolated in 3D. Changing floor order, IDs, aisle/station numbers, or rack specification can change addresses; existing records, mappings, and rules must remain valid.

This release includes outline drawing/vertex movement, gridded placement, drag/drop modules, planning rectangles, auto-fill, even spacing, per-aisle bin capacities, history, a fixed equipment catalog, robot waypoints, source/destination configuration and illustrative playback. Aisle, dock, section, level, bin, station and floor counts, site dimensions, module coordinates, outline vertex counts and total address counts have no fixed product ceiling. Physical containment, collision, frontage and clear-height validation still apply. Hundreds of aisles must retain complete addresses in both generation paths and drafts. No objects may silently disappear to satisfy a rendering or address budget. Geometry stays in meters internally; all user-facing lengths use feet and areas use ft². New warehouses default to a 50 ft roof; saved heights retain their original values. Footprints and fixture collisions are validated; this is not a structural, fire-code or robot safety certification.

Custom 3D renders the saved polygons, rotations, rack dimensions, stacked floors, docked trucks, equipment and routes. Selectable bins and equipment inspections supplement the address directory. Floor selection supports independent first-person exploration; stair/lift geometry does not provide continuous vertical traversal. Major edits occur in 2D.

Automation lab now persists local route-circuit queues, priority ordering, per-robot availability, conservative traffic holds, illustrative battery/charger state and logical conveyor buffer handoffs. Commands never control hardware or mutate inventory. Open robot routes return along their saved waypoints; this is route rehearsal, not WMS transport-order execution. Simulation positions drive the custom 3D scene; regular warehouse views no longer animate robots independently of saved simulation state. Design edits reset simulation state. Remaining work includes live telemetry/adapters, automatic charging dispatch, deadlock recovery, route-network policies, physical equipment handshakes and real transport mission execution. SCOTI integration awaits supported documentation. Roles and deployment verification remain release requirements.

Design drafts are independent from operational warehouses. Users can save structurally valid unfinished designs, including unresolved spatial issues, and resume them from the dashboard. The 2D studio supports debounced autosave, explicit save and revision conflicts. Draft completion follows a successful warehouse write; failure to complete the draft retains it safely. Operational validation is still required before creating/updating a warehouse.

Visual regression policy: unchanged converted flow templates use the existing detailed scene. Custom layout geometry includes textured concrete/cartons, rack bracing/feet/protectors and lane markings, cladding/windows and high-bay fixtures. A new design path must preserve or improve the established rendering standard.

Editor refinements include arrow-key movement (Shift for five grid steps), numeric waypoint editing, robot-route translation with numeric or pointer placement, full rear dock-edge alignment and exact upper-floor boundary containment. Auto-fill only applies to storage, staging and packing. Applying a design or navigating through workspace links flushes an available draft save; failed navigation saves keep the editor open. Pending changes trigger a browser unload warning. Offline persistence is not guaranteed; verify the saved status before closing the browser.

## Builder refinement — 2026-10-07

Template automatic arrangement grows the shell for configured shelves, doors and stations without lowering counts. Building length changes can fit whole rack sections when automatic aisle length is enabled; explicit section input switches to manual length. Automatic arrangement clears manual zone offsets; turn it off to preserve manual placement. The last template change can be undone.

Custom resizing scales floor outlines and module centers, stretches planning rectangles and fits aisle section counts to the new longitudinal span. Physical equipment dimensions remain unchanged; dock rear edges stay anchored to their wall. Automatic placement repairs fixtures outside changed shapes where space permits, without renumbering or deleting them. Unresolved placements remain visible as errors. Spatial undo/redo restores both design and site dimensions. Roof clearance can grow with rack specification changes. Geometry reductions remain subject to saved inventory, alias and capacity-rule validation.

Large scenes use dimension-aware camera/shadow ranges, indexed module address lookups, batched geometry and instanced stock. Decorative rack labels/2D section strokes may be sampled; aisle count, address generation and selection are not sampled. Browser memory/GPU resources remain finite; there is no claim of unlimited device capacity.
